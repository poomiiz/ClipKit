# EK-07 progress: cue ownership and motion safety

Status: **in progress**. This checkpoint is part of the full EK-07 work order. It does not complete semantic motion placement or certify a new clip.

- Shared ownership distinguishes decoration, replacement of named cue/roles, and an explicit full-card caption policy. ASS, HyperFrames and native serialization consume the same visibility decision. Native output no longer applies a second blanket mask to canonical subtitle events.
- New sentence-pair overlays derive ownership only from the selected cue's actual events, retain their parameters and use the generated event duration. Emphasis-only replacement keeps the normal text. Existing MOV-only records keep their conservative legacy behavior and require review. New generic hook/stat overlays default to decoration and preserve captions.
- Overlay edits/removal can identify a stable placement ID. A nearby start time no longer authorizes deletion/replacement; legacy removal requires a unique exact time. Measured text/subject-zone conflicts reject before rendering; simultaneous motion still uses conservative temporal rejection.
- Inserts expose their existing whole-word/phrase anchor resolver for motion reuse without changing indices or rounding clocks. The new ownership module participates in AI revision fingerprints.
- Direct generic motion requests use the existing field validation: nonfinite values, unknown fields and oversized text reject. Draft templates stay out of menus/rendering. Hook text is escaped in the template; failed/exceptional renders remove only their own partial target, retaining previous assets.

## Whole motion-list import

Browser/local answer imports now use the manual editor's read-only motion preparer for the entire desired list before calling any renderer. An invalid second placement, short interval or overlapping request allocates no motion assets. Generated files remain inside the existing recoverable AI transaction; a later encoding failure leaves original metadata and media intact.

The contract distinguishes omission (preserve), `[]` (clear placement metadata, retain original assets) and a nonempty list (replace all placements). Requests carry actual word/phrase anchors, placement, ownership and a content reason. Exported words now include their explicit one-based indices and retain full clock precision. Prompt/schema describe the same rules.
