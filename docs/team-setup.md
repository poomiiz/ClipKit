# เปิดระบบทีมตัดต่อ

## ผู้ดูแลบริการ (ครั้งเดียว)

1. ใช้ Supabase โครงการเดิม เปิด Email/Password และ Confirm email ใน Authentication ตั้งค่า SMTP และ Redirect URL ให้ตรงกับหน้าที่ใช้ยืนยันบัญชีจริง
2. ตรวจและติดตั้ง `supabase/migrations/20261011000000_organizations.sql` ในโครงการนั้น ก่อนเปิดให้ผู้ใช้สมัคร ข้อมูลทีม preset เดิมใช้คนละตารางและยังอยู่ตามเดิม
3. ใน ClipKit เปิด **ตั้งค่า → ระบบทีม** ใส่ Supabase URL และ Publishable / anon key ห้ามใส่ service role key หรือรหัสฐานข้อมูล หน้านี้ตั้งค่าบริการของเครื่อง ไม่ใช่สิทธิ์เจ้าขององค์กร
4. Google Drive: เปิด Drive API และสร้าง OAuth Client แบบ Desktop app ใน Google Cloud โครงการเดียวกันทุกเครื่อง ใส่ Client ID และ Client secret ในแท็บระบบทีม Client secret ไม่ถูกส่งกลับจาก API ตั้งค่า เก็บใน config.json ของเครื่องที่ไม่ขึ้น Git

5. ตั้ง OAuth consent screen / test users ให้พร้อม แอปขอ scope `drive` เพื่อรับส่งในโฟลเดอร์ที่มีอยู่แล้ว สมาชิกแต่ละคนต้องมีสิทธิ์ในโฟลเดอร์นั้นเอง การออกสู่ผู้ใช้ทั่วไปต้องผ่านขั้นตอนตรวจสอบ scope ของ Google ก่อน

การใส่ค่าเชื่อมต่อไม่ส่งไฟล์โดยอัตโนมัติ สมาชิกเปิดหน้าทีม กดเชื่อม Google Drive อนุญาตในเบราว์เซอร์ระบบ แล้วเลือกฟุตส่งขึ้นหรือรับเข้าเครื่องได้ โฟลเดอร์องค์กรตั้งโดยเจ้าของ ไฟล์คนละรุ่นเก็บแยกและตรวจ SHA256 ตอนรับ ชื่อและโฟลเดอร์ในเครื่องมาจาก UUID ขององค์กรและฟุต

รองรับฟุตและโปรเจกต์ CapCut เลือกโปรเจกต์ในเครื่องจากหน้าทีมแล้วส่งแพ็ก สมาชิกและหัวหน้ารับเข้าโฟลเดอร์ CapCut ของตนได้ ต้องปิด CapCut ตอนส่ง/รับ งานที่รับจะมีรหัสใหม่และไม่ทับโปรเจกต์เดิม รายชื่อ CapCut ถูกสำรองก่อนเพิ่มงาน หากรายชื่อเปลี่ยนหรือเขียนไม่ได้จะยกเลิกการนำเข้า

ตั้งค่าโฟลเดอร์ฟุต เพลง เสียง เอฟเฟกต์ CapCut และฟอนต์ที่ใช้งานใน **ตั้งค่า → โฟลเดอร์** แพ็กรวมไฟล์ที่โปรเจกต์อ้างถึง สื่อที่หายหรือนอกโฟลเดอร์ที่อนุญาตจะหยุดส่งพร้อมแจ้งชื่อไฟล์ ฟุตขนาดใหญ่ถูกอ่านเป็นชิ้น ไม่โหลดทั้งหมดเข้าหน่วยความจำ

## ผู้ใช้

- เปิด **ทีม → สมัครบัญชีใหม่** ใช้อีเมล Google ที่จะใช้ Drive ยืนยันอีเมลแล้วเข้าสู่ระบบ
- สร้างองค์กรเองได้ ผู้สร้างเป็นเจ้าขององค์กร
- เจ้าของเพิ่มสมาชิกด้วยอีเมลที่สมัครและยืนยันแล้ว เลือกคนตัดหรือหัวหน้าตรวจงาน
- เจ้าของเชื่อม Drive แล้วบันทึกโฟลเดอร์เฉพาะองค์กร ระบบให้สิทธิ์อ่าน/ส่งไฟล์แก่สมาชิกปัจจุบัน เมื่อเพิ่มสมาชิกใหม่จะให้สิทธิ์ Drive ด้วย หากให้สิทธิ์ไม่ครบจะแจ้งให้เจ้าของตรวจบัญชีและลองใหม่ ไม่อ้างว่าแชร์สำเร็จ
- ทุกคนในองค์กรเห็นรายการฟุต โปรเจกต์ สมาชิก และประวัติขององค์กรตนเอง
- คนตัดส่งงานหลายรายการให้หัวหน้าตรวจได้ หัวหน้าตัดสินใจจากหน้า **ตรวจงานทีม**

## สถานะและผู้ตัดสินใจ

| สถานะ | ผู้เปลี่ยน | ขั้นต่อไป |
|---|---|---|
| ✂️ กำลังตัด | คนตัดเริ่มงาน / หัวหน้าเปิดงานที่อนุมัติแล้วพร้อมเหตุผล | คนตัดส่งหัวหน้าตรวจ |
| 📤 รอหัวหน้าตรวจ | คนตัดส่งงาน | หัวหน้าผ่านงานไปให้ลูกค้าหรือส่งกลับแก้ |
| ⏳ รอลูกค้าตรวจ | หัวหน้าผ่านงาน | หัวหน้าบันทึกคำตอบลูกค้า |
| 🛠️ ส่งกลับแก้ | หัวหน้าระบุจุดแก้ | คนตัดแก้และส่งตรวจใหม่ |
| ✅ ลูกค้าอนุมัติ | หัวหน้าระบุหลักฐานคำยืนยันลูกค้า | ปิดรอบตรวจ เปิดแก้อีกครั้งต้องมีเหตุผล |

การตัดสินใจหลายรายการเป็นธุรกรรมเดียว หากรุ่นใดเปลี่ยนหรือข้ามองค์กร ระบบยกเลิกทั้งชุดให้โหลดใหม่ ผู้ตัดสินใจมาจากบัญชีที่เข้าสู่ระบบ ผู้ใช้แก้ชื่อผู้ตัดสินใจเองไม่ได้

สถานะเดิม 56 โปรเจกต์ในเครื่องยังเก็บไว้เป็นข้อมูลเดิม ไม่มีการอ้างว่าเป็นการตัดสินใจจากหัวหน้าหรือย้ายเข้าบัญชีองค์กรโดยอัตโนมัติ ต้องเลือกรายการและองค์กรปลายทางก่อนย้าย

หลังส่งแพ็กงานเดิมแล้ว หัวหน้าเลือกหลายโปรเจกต์ในหน้าตรวจ เลือก **รอลูกค้าตรวจ** ติ๊ก **ยืนยันงานเดิมที่รอลูกค้าตรวจแล้ว** และบันทึกที่มาของสถานะ ระบบเก็บผู้ยืนยันการนำเข้าแยกจากการอ้างว่าเป็นผู้ตัดสินใจในอดีต คนตัดยืนยันการนำเข้าสถานะไม่ได้ งานใหม่ต้องส่งแพ็กก่อนส่งหัวหน้าตรวจ

## ขอบเขตที่ตรวจแล้ว

- ฐานข้อมูลจำลองแยก: ป้องกันข้อมูลข้ามองค์กร, คนตัดอนุมัติไม่ได้, ตรวจรุ่นก่อนเปลี่ยนหลายงาน, ประวัติระบุบัญชีจริง
- ตัวเชื่อมบัญชีในเครื่อง: cookie HttpOnly, ป้องกันคำขอจากเว็บอื่น, ไม่ส่ง access/refresh token ไปเบราว์เซอร์, ปฏิเสธ service key
- ตัวเชื่อม Drive ใช้ provider จำลอง: OAuth state/PKCE ผ่าน loopback, รับส่งเป็นชิ้น, ที่อยู่รับไฟล์ต้องเป็น Google, hash ต้องตรง, ไม่ทับฟุตที่แก้ในเครื่อง, บันทึกรุ่นโดยตรวจความขัดแย้ง
- แพ็ก CapCut ในสองโฟลเดอร์ทดสอบ: เชื่อมสื่อ/รูปปก/JSON ซ้อน เปลี่ยนรหัสโปรเจกต์ใหม่ รักษาต้นฉบับ ป้องกันแพ็กข้ามโฟลเดอร์ และคืนงานเมื่อรายชื่อ CapCut เขียนไม่ได้
- ยังไม่ใช่หลักฐานสมัครจริงบน Supabase หรือซิงก์ไฟล์จริงบน Drive ต้องตรวจบนบริการที่ผู้ดูแลตั้งค่าแล้ว

บัญชีในเครื่องหมดอายุภายใน 24 ชั่วโมงและออกจากระบบเมื่อโปรแกรมเริ่มใหม่

อ้างอิงการเชื่อม: [Google Desktop OAuth](https://developers.google.com/identity/protocols/oauth2/native-app), [Drive resumable uploads](https://developers.google.com/workspace/drive/api/guides/manage-uploads)
