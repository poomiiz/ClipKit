# ระบบทีม ClipKit

## ตั้งค่าบัญชีกลาง

ใช้ Supabase โครงการเดิม เปิดยืนยันอีเมล และติดตั้ง migrations ตามลำดับใน `supabase/migrations/` ผ่านผู้ดูแลฐานข้อมูล แล้วใส่ URL กับ Publishable/anon key ใน **ตั้งค่า → ระบบทีม** ห้ามใส่ service role key

ผู้ใช้สมัครเอง ผู้สร้างองค์กรเป็น `admin` ผู้ดูแลเพิ่มสมาชิกที่สมัครและยืนยันอีเมลแล้วเป็น `lead` หรือ `editor` หนึ่งบัญชีอยู่หนึ่งองค์กร สมาชิกเดิมและแพ็ก preset ถูกผูกกับองค์กรเดิมโดย migration โดยไม่สร้างบัญชีใหม่ หากข้อมูลสมาชิกเดิมกำกวมหรืออยู่หลายองค์กร migration จะหยุดให้ผู้ดูแลแก้ข้อมูลก่อน

## ไฟล์ทีม

องค์กรเลือก Syncthing หรือ Google Drive for desktop และแชร์โฟลเดอร์ให้สมาชิกด้วยเครื่องมือนั้น ใน **ทีม → ตั้งค่าโฟลเดอร์ทีมในเครื่องนี้** เลือกเครื่องมือและโฟลเดอร์ที่มีอยู่แล้ว ตั้งค่าเครื่องมือให้ซิงก์เฉพาะ `footage/` กับ `exports/` ห้ามซิงก์โฟลเดอร์โปรเจกต์ CapCut/HyperFrames หรือโฟลเดอร์ติดตั้ง ClipKit

ClipKit ตรวจว่าโฟลเดอร์มีอยู่และเขียนได้ `doctor.py` ตรวจซ้ำได้ ฟุตอ้างอิงชื่อไฟล์กับขนาดที่แน่นอนในองค์กร ไม่ใช้ path บนเครื่องเป็น ID ฟุตที่ยังมาไม่ครบแสดง “ยังไม่ได้ sync” สถานะ เจ้าของ และประวัติอยู่ใน Supabase เท่านั้น

## รับงานและตรวจงาน

1. วางฟุตใน `footage/` เมื่อไฟล์พร้อมแล้วเลือกเพิ่มฟุต และเพิ่มเรื่องบรรทัดละหนึ่งเรื่อง รายการใหม่ยังไม่มีเจ้าของ
2. คนตัดกด **รับงาน** ฐานข้อมูลเปลี่ยนเจ้าของเฉพาะงานที่ยังว่าง ป้องกันรับซ้ำ เจ้าของผูกโปรเจกต์ส่วนตัวในเครื่องแล้วเปิดแก้
3. ส่งออก MP4 ลง `exports/` แล้วเลือก **ส่ง MP4 ตรวจ** → **👀 รอลูกค้าตรวจ** คนตัดเปลี่ยนผลตรวจไม่ได้
4. หัวหน้าเปิดหน้าตรวจงาน ตรวจ MP4 แล้วเลือกหลายงานเพื่อ **🔁 ต้องแก้** หรือ **✅ อนุมัติแล้ว** พร้อมบันทึกคำตอบลูกค้า งานอนุมัติถูกล็อกและเก็บคนอนุมัติกับเวลา
5. งานต้องแก้กลับเป็น **✂️ กำลังทำ** เมื่อเจ้าของเปิดแก้ หัวหน้าปลดล็อกหลังอนุมัติหรือโอนงานได้โดยระบุเหตุผล ประวัติเก็บเจ้าของเดิม เจ้าของใหม่ ผู้โอน และเวลา

หน้าโปรเจกต์กรองงานของฉัน/ยังไม่มีคนรับได้ หน้าหัวหน้ากรองงานรอตรวจ/อนุมัติ/ทุกงาน การส่งหลายงานใช้ MP4 ที่ผูกไว้แล้ว แต่ละงานต้องเป็นของผู้ส่งและอยู่ในสถานะส่งตรวจได้ รายการทั้งหมดล้มเหลวพร้อมกันหากงานใดเปลี่ยนไปแล้ว

## ข้อจำกัดและหลักฐานที่ยังต้องตรวจ

- โอนงานแล้วเจ้าของเดิมส่งโปรเจกต์ให้เจ้าของใหม่โดยตรง ไม่วางในโฟลเดอร์ซิงก์ทีม ไฟล์ตรวจงานเป็น MP4 ตามที่ผู้ใช้ยืนยัน วิธีส่งโปรเจกต์ข้ามเจ้าของยังต้องกำหนดก่อนใช้งานโอนจริง
- API ของ ClipKit ตรวจเจ้าของและสถานะก่อนเข้าถึงโปรเจกต์ที่ผูกกับทีม แต่ไม่สามารถห้าม CapCut เปิดสำเนาเก่าที่ค้างบนเครื่องเจ้าของเดิม ต้องจัดการสำเนาและสิทธิ์บนเครื่องนั้นก่อนรับรองการล็อกไฟล์โดยตรง
- การยืนยันสถานะเดิม 56 งานยังอยู่ในข้อมูลประวัติบนเครื่อง ไม่มีการสร้างเจ้าของหรือยืนยัน MP4 บน Supabase โดยเดา
- ยังไม่ตรวจการสมัครจริง/ฐานข้อมูล Supabase ที่ติดตั้งจริง/การซิงก์จริงจากสองเครื่อง ทั้ง Syncthing และ Drive for desktop รวมถึงไฟล์ online-only ความเร็วเน็ตและพื้นที่เก็บไฟล์
- ตรวจในเครื่องผ่าน `python scripts/team_workspace_test.py`, `python scripts/team_hub_test.py`, `python scripts/window_lifecycle_test.py` และ SQL `supabase/tests/owner_workspace_test.sql` บน PostgreSQL แยกจากระบบจริง การทดสอบ SQL ครอบคลุมสิทธิ์องค์กร เจ้าของ รับงานซ้ำ หัวหน้า และ rollback หลายงาน
- ตรวจ migration ทั้งกรณีทีมเดิมว่างและมีสมาชิก/preset เดิมแล้ว ภาพหน้าจอ UI ใช้ข้อมูลจำลอง ไม่ใช่หลักฐานการซิงก์จริง

## ชื่อเรื่องและข้อมูลข้ามเครื่อง

เจ้าของเปลี่ยนชื่อเรื่องจากหน้าทีม ข้อมูลชื่ออยู่ใน Supabase โฟลเดอร์โปรเจกต์ส่วนตัวใช้ชื่อเดิมเพื่อรักษาการผูกสิทธิ์ หน้าทีมอ่านสถานะล่าสุดทุก 15 วินาทีขณะว่าง โดยไม่ทับแบบฟอร์ม การเลือกโอนงาน หรือไฟล์ที่กำลังเลือกอยู่ ตรวจผ่าน `node scripts/team_refresh_test.js`

หน้าแรกอ่านสถานะจาก Supabase สำหรับโปรเจกต์ที่ผูกกับทีม สถานะเก่าของงานที่ยังไม่ผูกถูกระบุเป็นประวัติ หากยังไม่เข้าสู่ระบบหรือผู้ให้บริการขัดข้องจะแสดงเหตุผลแทนการใช้สถานะเก่าแทน หน้าตรวจงานตรวจสิทธิ์ admin/lead ที่เซิร์ฟเวอร์ก่อนแสดงหน้า ฟุตที่ซิงก์ครบมีปุ่มสร้างโปรเจกต์และการลากไฟล์ค้นหาในโฟลเดอร์ footage ของทีมได้
