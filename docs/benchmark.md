# วัดว่า EditorKrab ลดเวลาตัดต่อได้กี่ %

คำถามที่ตอบ: คลิปต้นฉบับยาว X นาที คนตัดเองใช้กี่นาที ใช้ EditorKrab แล้วเหลือกี่นาที ประหยัดกี่ % และเร็วขึ้นกี่เท่า

## เทียบอะไรกับอะไร
- **manual**: ตัดใน CapCut เองตั้งแต่เปิดไฟล์ดิบจนได้คลิปที่ผ่าน checklist ด้านล่าง
- **editorkrab**: `python scripts/run_clip.py "<video>" --all --capcut` (หรือกดในหน้าเว็บ) แล้วคนแก้ต่อใน CapCut จนผ่าน checklist เดียวกัน
- ทั้งสองแบบต้องจบที่ **คุณภาพเดียวกัน** ไม่อย่างนั้นตัวเลขเทียบกันไม่ได้

## ชุดคลิปทดสอบ
| length_group | ต้นฉบับ | format | ผลลัพธ์ที่ต้องได้ |
|---|---|---|---|
| 1 | ~1 นาที | short | 1 คลิปสั้น |
| 5 | ~5 นาที | short | 2-3 คลิปสั้น |
| 20 | ~20 นาที | short + long | 5+ คลิปสั้น หรือ 1 คลิปยาว |
| 60 | ~60 นาที | short + long | 10+ คลิปสั้น หรือ 1 คลิปยาว |

- แต่ละกลุ่มใช้คลิป **2 ตัวที่คล้ายกัน** (คนพูดคนเดียวกัน ความยาวต่างกันไม่เกิน 10%) เรียกว่า A และ B
- คนตัดคนเดียวกันห้ามตัดคลิปเดียวกันสองรอบ เพราะรอบสองจะเร็วขึ้นเองจากที่จำเนื้อหาได้ ให้สลับกัน: คนที่ 1 ตัด A แบบ manual และ B แบบ editorkrab ส่วนคนที่ 2 ตัด A แบบ editorkrab และ B แบบ manual
- ขั้นต่ำ 2 คนต่อกลุ่ม ถ้ามีคนเดียวให้ทำ A manual และ B editorkrab และหมายเหตุว่าเป็น UNKNOWN เรื่องความต่างระหว่างคลิป

## จับเวลาอะไร
| เวลา | ใครวัด | วัดยังไง |
|---|---|---|
| เวลาเครื่องแต่ละขั้น (ถอดเสียง, ทำโปรเจกต์, b-roll, ปก, CapCut ...) | อัตโนมัติ | `run_clip.py` เขียนลง `<output>/logs/timings.jsonl` ทุกขั้น รวมทุกรอบที่รันซ้ำ |
| เวลาคน (`human_min`) | คนตัดจับเอง | เริ่มนับตอนเปิดไฟล์ (manual) หรือตอนเปิดโปรเจกต์ที่ EditorKrab ทำให้ (editorkrab) หยุดตอนผ่าน checklist ไม่นับช่วงพัก ถ้า EditorKrab ขอ `WAIT` ให้ agent หรือ web AI ช่วย เวลาที่คนต้องทำตรงนั้นนับเป็นเวลาคนด้วย |
| จำนวนจุดที่ต้องแก้ (`fixes`) | คนตัดนับเอง | นับทุกครั้งที่แก้สิ่งที่ EditorKrab ทำมา เช่น ซับผิด 1 คำ = 1, ตัดผิดจุด 1 จุด = 1 |

ตัวเลขที่ได้มีสองแบบ:
- **เวลาคนที่ประหยัด** = (manual − คนแก้ใน editorkrab) ÷ manual ตัวนี้ตอบว่าช่วยคนตัดได้แค่ไหน เพราะระหว่างเครื่องทำงานคนไปทำอย่างอื่นได้
- **เวลารวมที่ประหยัด** = (manual − คนแก้ − เวลาเครื่อง) ÷ manual ตัวนี้ตอบว่าส่งงานได้เร็วขึ้นแค่ไหน

## Checklist คุณภาพ (ต้องผ่านทุกข้อทั้งสองแบบ)
1. ซับตรงกับเสียง สะกดถูก ไม่มีคำตกหล่น
2. ไม่มีช่วงเงียบหรือพูดซ้ำเกิน 0.5 วินาที
3. หน้าคนพูดอยู่ในกรอบ ไม่โดน UI ของ TikTok/Reels/Shorts บัง (safe zone)
4. คำเน้นและ hook ช่วง 3 วินาทีแรกมีครบ
5. เสียงไม่แตก ไม่ดังเบาสลับกัน
6. ปก/ชื่อคลิปพร้อมลง
7. export เป็น MP4 ได้ ความยาวไม่เกินที่แพลตฟอร์มกำหนด

ถ้าข้อไหนไม่ผ่าน `qc_pass` = `n` และ `scripts/bench.py` จะไม่ยอมเอาแถวนั้นไปคิด

## กรอกผล
ชีท: [`benchmark-sheet.csv`](benchmark-sheet.csv) หนึ่งแถวต่อหนึ่งไฟล์ต้นฉบับต่อหนึ่งแบบ

| คอลัมน์ | ใส่อะไร |
|---|---|
| video | ชื่อไฟล์ต้นฉบับ ต้องตรงกับชื่อไฟล์ที่ใช้รัน (`bench.py` จับคู่กับ timings.jsonl ด้วยชื่อนี้) |
| source_min | ความยาวต้นฉบับ (นาที) |
| length_group | 1 / 5 / 20 / 60 |
| format | short / long |
| mode | manual / editorkrab |
| editor | ชื่อคนตัด |
| human_min | เวลาคน (นาที) |
| fixes | จำนวนจุดที่แก้ (manual เว้นว่าง) |
| qc_pass | y / n |
| notes | อะไรที่ผิดปกติ |

สรุปผล:
```
python scripts/bench.py docs/benchmark-sheet.csv
```
ได้ตารางต่อกลุ่ม: `manual_min`, `ek_human_min`, `ek_machine_min`, `editor_time_saved_pct`, `faster_x`, `wall_clock_saved_pct`, `fixes_avg`

4. ข้อจำกัด: จำนวนคน, คลิปที่ใช้, อะไรที่ยัง UNKNOWN
